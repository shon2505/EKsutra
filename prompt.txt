# 1. CORE CONCEPT

Eksutra is a middleware/interoperability layer between government departments.

It does NOT replace government portals.

It does NOT store the actual Aadhaar/PAN/marksheet documents.

Instead, when a government department verifies a document, Eksutra stores a secure verification assertion saying that the document was verified by a trusted department.

Example:

A citizen applies at Department A.

Department A verifies:

* Aadhaar
* PAN
* Driving Licence

The citizen gives consent for the verification status to be stored and reused for eligible government services.

Eksutra stores a JSON-style verification assertion:

{
"subjectId": "USER-1001",
"documentType": "PAN",
"status": "VERIFIED",
"verifiedBy": "Department A",
"verifiedAt": "2026-09-04",
"validUntil": "2026-10-04",
"purpose": "Government Service",
"consentId": "CONSENT-001"
}

The actual document must NOT be stored.

Later, the same citizen visits Department B and applies for a scholarship.

Department B requires:

* Aadhaar
* PAN
* Marksheet

The citizen selects:

"Use Eksutra"

Eksutra checks the available valid verification assertions.

It responds:

Aadhaar ✓ Already verified
PAN ✓ Already verified
Marksheet ✗ Not verified

Therefore Department B asks the citizen only for the marksheet.

This is the central demonstration.

# 12. DIGITAL SIGNATURE / SECURITY DEMONSTRATION

Implement a prototype integrity mechanism.

Every verification assertion must contain a digital signature or cryptographic integrity value.

The conceptual architecture is:

Department A verifies the document
↓
Department A signs the verification assertion
↓
Eksutra stores the signed assertion
↓
Department B requests verification
↓
Eksutra validates the signature
↓
Only valid assertions are returned

Use a standard cryptographic library.

Do NOT implement cryptography yourself.

For the prototype, use a secure standard signing mechanism supported by Node.js crypto/Web Crypto.

The code should clearly separate:

* assertion creation
* assertion signing
* signature verification

Do not expose private keys in the frontend.

Use environment variables or server-side configuration for demo keys/secrets.

Add an optional technical status:

"Signature: VALID"

Do not over-emphasize cryptography on the main UI.
